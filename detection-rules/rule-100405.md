# Rule 100405 — Ingress Tool Transfer Detection

## MITRE ATT&CK Mapping

| Field | Details |
|---|---|
| Rule ID | `100405` |
| Technique | **T1105 — Ingress Tool Transfer** |
| Tactic | **Command and Control** |
| Wazuh Level | **10 — High** |
| Primary Process | `certutil.exe` |
| Detection Logic | `certutil.exe` + `-urlcache` |
| Data Source | Windows Sysmon process-creation telemetry |
| Validation Result | **Blocked by Windows Defender** |

---

## 1. Detection Objective

The objective of Rule 100405 was to detect suspicious use of the Windows `certutil.exe` utility with the `-urlcache` argument.

`certutil.exe` is a legitimate Windows utility, but it can also be abused to retrieve files from remote locations.

The detection was therefore designed to identify a command-line pattern associated with potential ingress tool transfer activity.

---

## 2. MITRE ATT&CK Technique

**T1105 — Ingress Tool Transfer**

**Tactic:** Command and Control

Ingress Tool Transfer describes the transfer of tools or files into a compromised environment.

Attackers may use legitimate operating-system utilities to retrieve additional tools or payloads after gaining access to a system.

---

## 3. Detection Logic

The custom Wazuh rule monitors process-creation telemetry for:

```text
certutil.exe
```

combined with:

```text
-urlcache
```

The combination was selected as the observable behavior for this detection.

The rule was mapped to:

```text
T1105
```

and assigned Wazuh level:

```text
10
```

---

## 4. Detection Rule

The custom Wazuh rule was created in the Wazuh manager's local rules configuration.

The detection focuses on the execution of `certutil.exe` when the command line contains the `-urlcache` argument.

The rule uses Windows Sysmon process-creation telemetry as its primary data source.

---

## 5. Rule Validation

Before testing the detection, the Wazuh configuration was validated using:

```text
wazuh-analysisd -t
```

The configuration was successfully loaded without syntax errors.

The rule was then tested against the Windows endpoint in the isolated laboratory environment.

---

## 6. Attack Simulation

Atomic Red Team was used to attempt the T1105 Ingress Tool Transfer technique.

The simulation attempted to use `certutil.exe` to retrieve a file from a remote URL.

The test was conducted within the controlled laboratory environment.

---

## 7. Manual Validation Attempt

Because the automated simulation was prevented, a direct manual attempt was also performed.

The purpose of the manual attempt was to determine whether the prevention was caused by the Atomic Red Team tooling or by the endpoint security controls.

The manual execution was also prevented.

---

## 8. Simulation Result

### Status: Blocked by Windows Defender

Windows Defender prevented the attempted transfer behavior before the expected activity could execute successfully.

The attempt returned:

```text
Access is denied
```

The same prevention behavior was observed during:

- Atomic Red Team testing
- Direct manual testing

---

## 9. Detection Validation Status

### Important Distinction

Rule 100405 was successfully configured and associated with the correct MITRE ATT&CK technique.

However, the detection was **not successfully validated through a live-fire transfer event**.

The reason was that Windows Defender prevented the underlying behavior before successful execution.

The result can therefore be represented as:

```text
Detection Rule Created
        ↓
Configuration Validated
        ↓
T1105 Simulation Attempted
        ↓
Windows Defender Prevention
        ↓
Transfer Blocked
        ↓
No Successful Live-Fire Detection
```

---

## 10. Why This Is Not Automatically a Detection Failure

For a SIEM detection to successfully fire, the targeted behavior must normally execute sufficiently to generate observable telemetry.

In this test, the endpoint protection layer prevented the behavior before successful execution.

Therefore, the project demonstrated:

**Endpoint Prevention**

but did not demonstrate:

**Successful Wazuh Detection Validation**

These are separate security outcomes.

---

## 11. SOC Significance

Ingress Tool Transfer is important from a SOC perspective because attackers may need to introduce tools, scripts, or other files into a compromised environment.

The use of a legitimate Windows utility for this purpose can make detection more challenging.

Monitoring suspicious command-line combinations can provide useful endpoint visibility.

---

## 12. SOC Alert Triage

If Rule 100405 generated an alert in a production environment, the analyst should investigate:

- Endpoint
- User
- Process
- Parent process
- Command line
- Remote destination
- File being transferred
- Timestamp
- Related PowerShell activity
- Other network or endpoint events

The analyst should determine whether the transfer was authorized and whether the retrieved file was legitimate.

---

## 13. Severity Assessment

The Wazuh rule was assigned level:

```text
10
```

Under the project's severity model, this falls within the **High** severity range.

High-severity alerts require prompt investigation and escalation when appropriate.

The analyst should consider the context and determine whether there is evidence of malicious activity.

---

## 14. False Positive Considerations

`certutil.exe` is a legitimate Windows utility.

It may be used for legitimate certificate-related and administrative activities.

Therefore, the presence of `certutil.exe` alone should not automatically be considered malicious.

The detection focuses on the combination of:

```text
certutil.exe
+
-urlcache
```

The analyst should still investigate the complete command line and surrounding activity.

---

## 15. Investigation Questions

When investigating a potential Rule 100405 alert, the SOC analyst should ask:

### What was transferred?

Identify the requested file and its purpose.

### Where did it come from?

Review the remote URL or destination.

### Who initiated the activity?

Identify the associated user or account.

### What launched certutil?

Review the parent process.

### Was the activity authorized?

Determine whether the action was part of approved administration or software deployment.

### What happened afterward?

Search for additional execution, persistence, or suspicious endpoint activity.

## 21. Lessons Learned

This detection reinforced several important concepts:

- Legitimate Windows utilities can be abused for malicious purposes.
- Command-line context is important when detecting suspicious utility usage.
- T1105 is relevant to monitoring potential tool or file transfer activity.
- Endpoint prevention can stop a behavior before the SIEM observes successful execution.
- A blocked simulation should be documented rather than incorrectly reported as a successful detection.
- Detection validation should distinguish between rule configuration and successful live-fire execution.
- Security controls should not be weakened merely to make a laboratory test pass.

---
