---

## 1. Detection Objective

The objective of Rule 100402 was to detect execution of `systeminfo.exe` on the Windows endpoint.

The command can be used legitimately by administrators and users to obtain information about a Windows system. However, system information discovery is also a common activity during post-compromise reconnaissance.

The detection was therefore designed to identify execution of `systeminfo.exe` and provide the SOC analyst with an event that can be investigated in context.

---

## 2. MITRE ATT&CK Technique

**T1082 — System Information Discovery**

**Tactic:** Discovery

System Information Discovery involves obtaining information about the operating system and host environment.

An attacker may use this information to understand the characteristics of a compromised system and determine what actions may be appropriate next.

---

## 3. Detection Logic

The detection focuses on process-creation telemetry for:

```text
systeminfo.exe
```

The rule identifies execution of the Windows system-information utility through the endpoint process-creation data collected by Wazuh.

The project primarily used Sysmon Event ID 1 as the process-creation data source.

---

## 4. Detection Rule

The custom rule was created in the Wazuh manager's local rules configuration.

The rule was mapped to:

```text
T1082
```

and assigned Wazuh level:

```text
5
```

The detection logic focuses on `systeminfo.exe` process creation.

---

## 5. Rule Validation

Before testing the detection, the Wazuh configuration was validated using:

```text
wazuh-analysisd -t
```

This was used to confirm that the Wazuh configuration could be loaded without errors.

The rule was then tested against the Windows endpoint in the isolated laboratory environment.

---

## 6. Attack Simulation

Atomic Red Team was used to simulate the T1082 System Information Discovery technique.

The selected test executed:

```text
systeminfo.exe
```

on the Windows endpoint.

The resulting endpoint telemetry showed execution of:

```text
C:\Windows\System32\systeminfo.exe
```

---

## 7. Detection Result

### Status: Successfully Fired

Rule 100402 fired on the **first attempt** during Atomic Red Team testing.

The generated telemetry contained the execution of `systeminfo.exe`.

The parent command line also showed `systeminfo` chained with a registry query.

This was consistent with a scripted reconnaissance step rather than simple manual execution.

---

## 8. Alert Investigation

When investigating a Rule 100402 alert, the analyst should review the available process-creation context.

Important investigation fields include:

- Timestamp
- Endpoint
- User
- Process image
- Parent process
- Parent command line
- Command line
- Related discovery commands
- Other alerts from the same endpoint

The parent process and command line are particularly useful because they can help distinguish isolated legitimate administration from a broader reconnaissance sequence.

## 11. False Positive Considerations

`systeminfo.exe` is a legitimate Windows utility.

It may be executed by:

- System administrators
- IT support personnel
- Troubleshooting scripts
- Configuration and inventory tools
- Legitimate system-management software

Therefore, execution of `systeminfo.exe` should not automatically be considered malicious.

The analyst should examine the surrounding activity and determine why the command was executed.

### Questions for the Analyst

- Who executed `systeminfo.exe`?
- Was the user authorized to perform system administration?
- What process launched it?
- What was the parent command line?
- Were other discovery commands executed?
- Did suspicious activity occur immediately before or after the alert?
- Is the endpoint showing signs of compromise?

## 15. Why the Parent Command Line Matters

The alert contained additional process context beyond simply showing that `systeminfo.exe` executed.

The parent command line showed `systeminfo` chained with a registry query.

This is useful from a SOC perspective because a sequence of discovery commands can provide stronger context than one isolated command.

An analyst should therefore avoid investigating the alert as a completely standalone event.

Instead, the analyst should examine surrounding process activity and determine whether multiple discovery behaviors occurred as part of a broader sequence.

---

## 16. Detection Engineering Takeaway

This rule demonstrated how a common Windows utility can become a useful security detection when its execution is monitored and investigated in context.

The key lesson is:

```text
Legitimate Tool
      +
Suspicious Context
      =
Potential Detection Opportunity
```

`systeminfo.exe` is not inherently malicious.

The value of the detection comes from identifying its execution and giving the analyst enough context to determine whether the activity is expected or suspicious.

---

## 17. Lessons Learned

This detection reinforced several important SOC concepts:

- Discovery activity can occur after an attacker gains access to a system.
- Process-creation telemetry provides useful endpoint visibility.
- Legitimate Windows utilities can be abused during reconnaissance.
- A detection alert does not automatically mean malicious activity.
- Parent-process and command-line information are important during triage.
- Multiple related discovery commands can provide stronger investigative context.
- MITRE ATT&CK can be used to organize and communicate detection coverage.
